3. Задание 1
В задании были проведены пять экспериментов с DOM и событиями.
Эксперимент 1
Проверялась работа querySelector и querySelectorAll при отсутствии подходящих элементов.
Прогноз:
querySelector вернёт null.
querySelectorAll вернёт пустую коллекцию длиной 0.
Фактический результат:
Отсутствующий элемент: null

querySelector возвращает null, если элемент не найден.
querySelectorAll возвращает пустой NodeList.
Эксперимент 2
Проверялось чтение data-task-id через dataset.
Для кнопки было указано:
data-task-id="23"
Прогноз:
dataset.taskId = "23"
Тип: string

После Number():
23
Тип: number
Фактический результат:
dataset.taskId: 23 string
Числовой id: 23
Значения из dataset читаются как строки, поэтому перед передачей id в функции ПР2 значение преобразуется через Number().
Эксперимент 3
Проверялась работа NodeList после добавления новых элементов.
Исходное количество элементов:
1
После первого нажатия кнопки "Добавить запись":
Старый NodeList: 1
Новый querySelectorAll: 2
После второго нажатия:
Старый NodeList: 1
Новый querySelectorAll: 3
querySelectorAll возвращает статический NodeList.
Ранее сохранённая коллекция не изменяется после добавления новых элементов. Для получения актуальных элементов необходимо выполнить новый querySelectorAll.
Эксперимент 4
Проверялась работа textContent.
После нажатия на кнопку заголовок получил значение:

На странице строка отображалась полностью вместе с тегами strong.
HTML-элемент strong создан не был.
Это связано с тем, что textContent воспринимает переданное значение как обычный текст, а не как HTML-разметку.
Эксперимент 5
Нажатие выполнялось непосредственно по вложенному span с id lab-label.
Фактический журнал:
phase=1; target=lab-label; currentTarget=lab-card
phase=3; target=lab-label; currentTarget=lab-button
phase=3; target=lab-label; currentTarget=lab-card
event.target во всех обработчиках оставался lab-label, так как именно по нему было выполнено нажатие.
event.currentTarget изменялся в зависимости от элемента, обработчик которого выполнялся.
Сначала событие прошло фазу захвата через контейнер, после чего всплыло через кнопку обратно к контейнеру.
4. Задание 2
В файле task-view.js были реализованы функции:
createTaskElement()
renderTaskList()
createTaskElement создаёт DOM-элемент карточки задачи.
Карточка содержит:
название задачи
статус
приоритет
кнопку изменения статуса
кнопку удаления
Идентификатор задачи записывается в:
data-task-id
Для выполненной задачи добавляется класс:
is-completed
Название задачи выводится через textContent, поэтому текст не интерпретируется как HTML.
renderTaskList создаёт карточки для переданного массива и заменяет старое содержимое списка.
Повторный вызов функции не создаёт дубликаты карточек.
5. Задание 3
В main.js был реализован обработчик:
handleTaskListClick()
Для обработки кнопок используется делегирование событий.
Один обработчик назначен на общий контейнер списка.
Для поиска кнопки используется:
event.target.closest("button[data-action]")
Поэтому обработка работает даже при нажатии на span внутри кнопки.
Поддерживаются два действия:
toggle
delete
При toggle находится текущая задача и её completed изменяется на противоположное значение.
При delete задача удаляется из массива.
Изменение выполняется через функции из task-service.js.
После успешной операции обновляется currentTasks и повторно вызывается renderApp().
Исходный массив напрямую не изменяется.

12. Распределение файлов
data.js содержит общий набор задач и данные индивидуального варианта.
task-service.js содержит функции работы с задачами из ПР2 и не работает с DOM.
task-selectors.js отвечает за фильтрацию задач.
task-view.js отвечает за создание карточек и обновление элементов страницы.
main.js хранит текущее состояние приложения и обрабатывает события пользователя.
